**1200 с** — монотонный дедлайн принятия успешного решения супервизором, отсчитанный от начала VM-фазы. До 1170 с нужен штатный выход QEMU. Резерв до 1180 с для остановки и сбора прямого потомка, до 1187 с для serial проверки, до 1195 с для штатного rm, до 1198 с для TERM/KILL и сбора rm. После подтверждения rm и исходного inode vm штатное завершение прямого rmdir должно наблюдаться строго до 1197 с. Затем TERM с ожиданием до 0,35 с, KILL при необходимости и сбор до 1198 с. Своевременный ноль rmdir, отсутствие имени родителя и ноль ссылок исходного inode подтверждаются до 1198 с. До 1199 с зарезервировано для сбора процесса проверки, остаток — для финального решения. **30 минут** — отдельный максимальный timeout GitHub Actions job, включающий подготовку и VM-фазу. Синхронные операции после решения, включая закрытие дескрипторов и вывод результата, теоретически могут задержать фактический выход процесса. Дедлайн решения не доказывает жёсткую внешнюю отсечку всей VM-фазы. Если процесс не собран, рабочие файлы не удаляются супервизором, результат QEMU_STOP_UNCONFIRMED. При штатном выходе 0, точном единственном маркере гостя, последующей строке штатного выключения и подтверждённой очистке до дедлайна ожидается OFFLINE_ISO_READY и код 0. Сохранять в отчёте только run ID/attempt/commit, версию QEMU, KVM API, image/ISO/manifest hashes, фиксированные маркеры, длительности, код и статус очистки. ## Отказы очистки

Супервизор запускает rm через execve в прямом дочернем процессе с отдельным PGID. Перед удалением проверяются исходные device/inode собственного временного каталога. После кода rm 0 отсутствие каталога подтверждается lstat в отдельной ограниченной фазе. Опоздавший или ошибочный rm, оставшийся каталог и неподтверждённый сбор исключают успех. Код 22 обозначает исчерпанный бюджет, код 25 — неподтверждённый сбор rm или ошибку его супервизора. Код 21 обозначает ошибку rm или проверки отсутствия каталога. При одновременных ошибках отметки фаз сохраняются. Неподтверждённая остановка QEMU (23) имеет приоритет, иначе переполнение serial сохраняет код 24 даже при последующем отказе очистки.

Локальные заглушки не подтверждают поведение stdio backend QEMU на Actions. При SIGKILL супервизора, аварии runner или неотзывчивом ядре подтверждение остановки и очистки может отсутствовать. Успех требует наблюдаемого завершения и проверки в пределах общего бюджета.

## Финальный аудит идентичности очистки

Действует модель доверенного одноразового GitHub-hosted runner. Враждебный процесс с UID runner и его passwordless sudo считается компрометацией хоста. Preflight открывает канонический RUNNER_TEMP без перехода по symlink и проверяет тип, владельца, совпадение inode, права владельца на запись и проход, отсутствие записи для группы и остальных и отсутствие специальных битов. Режим 0700 для RUNNER_TEMP не обязателен, права существующего каталога не изменяются. Bootstrap создаёт через dir_fd уникальный подкаталог и его фиксированное дерево vm, оба с 0700. Единственный супервизор создаёт дерево и держит FD до итогового решения. Launch shell передаёт управление через exec до выделения рабочего каталога. Подготовительный Bash работает прямым потомком супервизора и получает только подтверждённый путь. Передачи имён и inode через stdout bootstrap больше нет. После выхода Bash супервизор проверяет квитанцию с пятью полями и повторно сверяет закреплённые каталоги и mounts до запуска QEMU.

Супервизор удерживает дескрипторы временной области, приватного родителя и исходного рабочего каталога до итогового решения. На Linux используется O_PATH вместе с O_DIRECTORY, O_NOFOLLOW и O_CLOEXEC. После fork дочерние процессы сразу закрывают копии этих дескрипторов. Проверка перед rm сверяет текущий путь с закреплённым inode. После подтверждённого кода rm 0 требуется отсутствие пути и fstat исходного объекта с теми же dev/ino и st_nlink == 0. Переименование исходного объекта с исчезновением имени не проходит эту проверку. Отсечки 1195/1198/1199 и дедлайн 1200 с сохранены. Ошибка fstat, lstat или потеря идентичности не дают PASS. До запуска VM, перед созданием процесса удаления и непосредственно перед exec проверяется mountinfo. Mount на рабочем каталоге или внутри него блокирует удаление, включая bind mounts с тем же st_dev. Непривилегированный GNU rm дополнительно использует --one-file-system. Между сверкой и exec остаётся окно для процесса, способного менять хост. Это остаточный риск принятой модели, которая опирается на доверие к runner и отсутствие конкурирующих операций в рабочем каталоге.

Локальные тесты используют только собственные временные деревья. На macOS успешная ветка Linux st_nlink == 0 моделируется после фактического удаления тестового каталога, поскольку Darwin сохраняет ненулевое значение для открытого каталога. Отрицательный сценарий с переименованием и сохранённым inode использует фактические fstat и lstat. На macOS inventory mountinfo проверен на синтетических записях, GNU rm заменён локальным адаптером BSD rm только в тестах. Реальная Linux-проверка остаётся NOT_RUN.

### Владение при отказе подготовки

Bootstrap фиксирует inode сразу после каждого mkdir. При отказе он удаляет в обратном порядке только подтверждённые пустые каталоги. Перед каждым удалением повторно проверяются идентичность и таблица mounts. Статус BOOTSTRAP_ROLLBACK и исходный errno выводятся отдельно. При отсутствии идентификации или несовпадении объект остаётся на месте.

При ошибке команд подготовки или отклонении квитанции подготовки супервизор сохраняет исходный код подготовки и запускает подтверждаемую очистку собственного дерева с отдельным резервом 10 с до старта VM-фазы. Обычный stdout/stderr подготовки подавлен. Публикуются отдельные фиксированные маркеры, код отказа, пять проверенных полей квитанции и статус отката. При INT/TERM супервизор передаёт сигнал подготовительному Bash, чей trap завершает его после возврата текущей foreground-команды. Если кооперативное завершение не наблюдается за 5 с, супервизор пытается остановить и собрать процесс в пределах следующих 2 с и оставляет дерево с CLEANUP_STATUS=unconfirmed. Жёсткая остановка или оставшийся процесс подготовки не позволяют доказать безопасность автоматической очистки. RUNNER_TEMP и его права не меняются.

## Final candidate: статус подготовки и атомарная диагностика

PREPARATION_TERMINATION различает exit, signal, not_started и unknown.
PREPARATION_EXIT_CODE появляется только при подтверждённом старте Bash и его обычном выходе через wait4.
PREPARATION_SIGNAL содержит номер сигнала; он не является обычным кодом Bash.
PREPARATION_POLICY_CODE — итог подготовки с приоритетом отмены (130/143).
PREPARATION_CANCELLED фиксируется отдельно. При потере наблюдения или принудительной остановке
откат запрещён, даже если позднее получен ноль. При ECHILD право сигнализировать PID/PGID отзывается.
Первый встроенный printf Bash подтверждает старт одним байтом в отдельном pipe и сразу закрывает FD.
Отказ fork/exec не выдаётся за исполненный Bash. Pipe не передаётся VM или гостю.

Квитанция отказа сверяется только с подтверждённым обычным ненулевым выходом Bash при безопасной остановке.
Сигнал, отсутствие наблюдения, несовпадение кода, неверный файл/формат дают PREP_STAGE=unknown.
EXIT-trap вызывает supervisor.py --write-preparation-failure; вспомогательный Python использует
O_WRONLY|O_CREAT|O_EXCL|O_NOFOLLOW|O_CLOEXEC|O_NONBLOCK, mode 0600, максимум 64 байта,
и проверяет полноту единственной записи. Существующие FIFO, symlink, файл или каталог не открываются
